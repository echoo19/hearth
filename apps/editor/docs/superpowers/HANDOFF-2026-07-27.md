# Where things stand, end of 2026-07-27

Read this first when picking the work back up. It records what was decided and
what is half-done, which the specs and plans do not.

## The arc of the day

Bot playtesting was investigated, found to be genre-bound (2D action games
only), and demoted to a purely passive capability the agent reaches for with no
user-facing surface. It was replaced as flagship by **the Private Tester**: an
LLM that plays your game, remembers every previous session, and answers "did
the change you just made help?"

The tester is BUILT and VERIFIED. Two live sessions ran against a real game
through a real model. Session 2 produced the payoff verbatim: *"this time I saw
the score reach 1 on picture 3, while last time I never collected any coins."*

## Governing principle, above everything else

Hearth supports any game people want to make with an agent and NEVER locks the
agent into a mold, a direction or an assumption. Using Hearth should be no
different from running a coding agent in a terminal and building from nothing.

The known violations, both pre-existing: `ProbeEntity` is `{id, x, y, alive}`
with no `z`, and `NavGrid` is a row-major 2D cell grid. They are why the bot
fleet only ever worked for platformers. Adding `z` is small and additive;
generalising `NavGrid` should wait for a real game that needs it. Do not add a
third.

## Blockers and decisions still open

**The product film is the largest inaccuracy on the site.** It shows the ember
Playtest button, a Playtests rail, and a line reading "Press Playtest when you
want the bots to have a go at it" for about three quarters of its 38 seconds,
and on its poster frame, which is the homepage's first paint. Every one of those
surfaces was deleted. An agent was dispatched to replace it; if that did not
land, the film must not ship as is.

**Do not deploy the site and do not merge `pivot` to `main` until the tester is
in a release.** Both the site and the README describe it, and it exists in the
repo but not in v1.5.0.

**Resolved, do not relitigate:** the OpenAI logo stays. Nominative compatibility
use, guidelines complied with, Jake's call.

## Smaller things found and deliberately left

- `hearth-website` `prebuild` runs `sync-docs.mjs` against the engine's working
  tree, so a build with a dirty engine checkout silently rewrites
  `src/content/docs/`. Always `git checkout -- src/content/docs/` after building
  there. It wants a clean-checkout guard, which nobody has verified against the
  Vercel deploy.
- `server/evidenceWatcher.ts` no longer contains a watcher, only two path
  constants. The name lies.
- `packages/playtest/src/bots/` still holds an older duplicate of the policy
  logic, untouched by any of this.
- `hearth-window@2x.png` is 670KB at 2880x1800 and serves as both an LCP image
  and the site-wide og:image.

## Standing rules that bit during the day

- Invoke the `humanizer` skill on outbound copy. Do not approximate it with
  "write plainly": it catches rhythm, and a pass found a beat where 13 of 14
  sentences opened with the same word and three headings built to one template.
- Invoke `impeccable` before building any surface.
- No em dashes anywhere.
- Never run two vitest runs at once. Never `git add -A`.
- One agent per repo at a time. Two committing into one git index will collide.
- A live end-to-end run is required before calling a feature done. Unit tests
  passed while the tester was leaking raw loop tokens into the UI.
