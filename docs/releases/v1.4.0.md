# Hearth v1.4.0

Hearth now opens the way you'd expect a chat app to open: straight into a
conversation. The folder picker that used to gate the window is gone.

## Chat-first home

With no folder open, the window is a greeting and a composer. Type what you
want to play and send it — Hearth makes a project folder for it under
`~/Hearth`, named from your words, opens it, and starts the conversation
there. Opening an existing folder is still one click away in the sidebar.

## A real sidebar

The left rail now carries the whole surface: search, a Chat | Terminal
switch, New chat, Open folder, your project folders, and a **Recents** list
of every conversation across every folder — click one and Hearth opens its
folder and picks the conversation back up. Connector and skill slots follow,
and the account row at the bottom shows who is signed in. When an update has
downloaded, a **Relaunch to update** banner appears above it; the old restart
dialog is gone.

## Pick the model per message

The composer gained a model selector. Claude models are listed with an
Anthropic API key; ChatGPT models are read live from your installed Codex —
including reasoning effort, which applies per message. Your choice rides
along with each turn.

Claude model choice binds when a conversation's agent starts, so a change
applies from the next new chat; ChatGPT switches take effect immediately.

## Coming from 1.3.0

Installed apps update automatically. Conversations and folders carry over
unchanged; `.hearth/chats` is the same format.

## Downloads

Desktop builds are attached below: macOS (`.dmg`), Windows (`.exe`), Linux
(`.AppImage` / `.deb`). macOS builds are Developer ID signed and notarized.
Windows builds are not code-signed yet, so SmartScreen may require
**More info → Run anyway** on first launch.

The release also includes standalone tools that run on any Node.js 20 or newer
installation, without the app:

- `hearth-cli.mjs` — the Hearth CLI.
- `hearth-mcp.mjs` — the MCP server, for Claude Code and other MCP clients.
- `hearth-player.js` — the web-export player; keep it beside the CLI, or set
  `HEARTH_TOOLS_DIR`, so `hearth export web` can find it.

Documentation: <https://github.com/echoo19/hearth#readme>
