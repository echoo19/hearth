# Hearth v1.6.0

Someone to play your game, an agent of your own choosing, and a clear answer to
how much rope that agent gets.

## The private tester

Press **Play** on the Tester tab and a model opens your game and plays it the
way a person would. It looks at the screen, decides what to try, tries it,
looks again. When it stops it writes up what it made of the game, and from the
second session on it answers the question you actually wanted asked: is this
better than last time, and did anything get worse.

The whole feature rests on it not overclaiming, because you are going to act on
what it says. So:

- Every claim points at a picture it took, and a proposal it cannot point at is
  dropped and counted out loud rather than smoothed over.
- It tells apart what it played its way to from what the game put it next to. A
  thing it never reached is not a thing it says you can reach.
- The verdict is only ever about the change since the last session, and it sees
  its own previous verdict only after it has written down what it saw.
- When it could not work something out, it says so instead of guessing. A
  session that crashed reports that it crashed; it does not report that your
  game is fine.

Its notes live in your project, in `.hearth/tester/`, including a `memory.md`
you can read and correct. A memory you cannot argue with is one you stop
listening to.

The report opens where you are standing, with a plan of action under it:
everything it proposed, nothing ticked. Tick what you agree with and the work
goes to your agent in a conversation of its own.

The **Tester** screen in the sidebar is a history across every game you have
made, newest first, and any row opens its report without switching project.

## Register your own agent

Hearth already drove Claude and, through the open-source Codex CLI, ChatGPT,
and it would run any CLI you liked in the terminal. Now you can register an
agent of your own and have it answer *in the conversation*, which is the part
the terminal could never do: the same transcript, saved the same way, replayed
the same way, and usable by the tester.

The protocol is newline-delimited JSON on stdin and stdout, and three event
types are enough to be useful. A wrapper around whatever you already use is
about thirty lines, and there is a complete one in
[custom-agents.md](../custom-agents.md).

Hearth does not inject instructions, facts or personalization into an agent you
brought. It supplies a prompt and renders what comes back.

## Permission modes

Three, chosen per project, on the composer:

- **Ask first.** Every write and every command waits for you. Reading is never
  interrupted.
- **Ask outside.** The default. Inside your project the agent gets on with the
  work; anything outside asks.
- **No checks.** Nothing asks, anywhere on the machine. Confirmed once, per
  project.

Every harness Hearth drives honours the setting. An agent you registered
yourself enforces its own, and Hearth says so on the turn rather than implying
it gated something it cannot.

The choice is stored on your machine, not in the project, so a repository you
push never carries it to whoever clones it.

## Naming, and where you are

Projects are named by you now, in a dialog, in any language you like. The first
message used to name the folder off your sentence with no chance to object.
Hearth keeps the name you typed and gives the folder a plainer version of it.

New chat, Skills and Tester belong to you rather than to a game, so standing on
one of them means no project is selected, and the sidebar says so.

## Please read this if you have pushed a project to git

Before this release, the `.gitignore` Hearth wrote into a new project did not
cover `.hearth/chats/`, `.hearth/tester/`, `.hearth/evidence/` or
`.hearth/app.json`. If you created a project with an earlier version and pushed
it to a remote, your conversation history, your playtest screenshots and **any
API key saved in that project** may be in that repository.

New projects are covered. Existing ones are not fixed retroactively, because
Hearth will not rewrite a git history you own. Check with:

```bash
git -C /path/to/your/project ls-files .hearth
```

If `app.json` is listed, treat the key in it as exposed: rotate it, then
`git rm --cached` the file and add the paths above to that project's
`.gitignore`.

Related: a project's `.claude/skills/` mirror is now ignored too. Hearth copies
your personal skills in there for the agent to read, and they are yours rather
than the game's.

## Also in this release

- The game pane serves your project over its own loopback origin, and that
  origin can no longer reach `.hearth`, `.git` or `.env`, including through a
  symlink.
- Conversations survive a torn index. A partial read is never written back, so
  recovery can no longer lose a chat it was meant to save.
- Two windows on one project can no longer interleave a send, and a
  conversation's events can no longer land in a different conversation.
- Switching between the game, the tester and the console keeps all three
  running. Leaving the game tab used to restart it.
- The tester can press keys the game names on its own screen, including the
  `R` that a game says restarts it.
- Settings tells a failed check apart from a negative answer, and every
  unknown row has something to press.
