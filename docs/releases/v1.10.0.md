# Hearth v1.10.0

Finished games can now go straight from the app to the Hearth catalog, and
Claude conversations run on Claude again, on the newest models.

## Publish to the catalog

A game in Hearth is already a folder of static web files, so publishing it
needs no export step. Add a catalog token once (it is checked against the
catalog before Hearth saves it, in `~/.hearth/catalog.json`), pick a cover from
inside the project, and publish. Publishing the same folder again updates its
listing instead of creating a second one, even after you rename the game.

Hearth never uploads your `.hearth/` folder, at any depth. It holds chat
transcripts and tester notes, and none of that belongs on a public page.

When a turn ends on a game that runs and has never been published, the top bar
offers a Publish button once per folder. The agent also knows the catalog
exists, so it can suggest the same step when a session wraps up.

## Claude runs on Claude

Builds up to v1.9.0 shipped without the Claude Agent SDK. A conversation set to
Claude quietly fell through to Codex, so a Claude chat could answer with
ChatGPT's errors, and the model menu was stuck on a built-in list.

- The app now bundles the SDK and runs the Claude Code you installed and
  signed into.
- If the agent you picked can't start, the turn says so. Hearth no longer
  answers with the other agent.
- The model menu reads its list from your installed Claude Code, so it shows
  current models (Opus 5.5, Sonnet 5.5, Fable 5.1, Haiku 4.5 today) and picks
  up new ones when Claude Code updates.
- A model picked from the old built-in list, or one that has since left the
  menu, moves to the newest model in its family. A specific older version you
  picked on purpose stays as it is.

## Also in this release

- The quickstart ends with where to put the finished game.
- The catalog's token page link points at its current address.
- Playtests on a slow or busy machine no longer miss a short key press: every
  step now waits for the game to draw at least one frame.
