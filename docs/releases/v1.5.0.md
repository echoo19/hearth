# Hearth v1.5.0

Three things you could do in a terminal and could not do in Hearth: show your
agent a picture, teach it something once and have it remembered, and see
everything it actually did.

## Show it something

Drop an image or a file onto the composer, paste one, or pick it from the **+**
menu. A message that is only a picture is a message — you don't have to type
anything with it.

Attachments are written into the project, under
`.hearth/chats/attachments/`, before the turn starts, so the transcript can
still show them after a restart. Images reach the model as pixels either way:
Codex is handed the path with a `localImage` item, Claude gets the bytes as an
image block. Anything else travels as a path, because the agent is already
sitting in the folder with its own file tools — pointing at a PDF or a zip is
more useful than pushing it through the context window.

Up to eight files per message, 12 MB each and 24 MB in total. Large PNGs, JPEGs
and WebPs are scaled down first, to the size both APIs would have scaled them
to anyway.

## Skills

A skill is a folder with a `SKILL.md` in it: a name, one sentence about when to
use it, then the instructions. That format is not Hearth's invention — it is
the one Claude Code and Codex both already read, which is why one skill works
with whichever agent answers.

The rail has a **Skills** fold and a panel behind it: search, and a **+** that
offers three ways to make one. Write it yourself in an editor, upload a folder
you already have, or hand the job to the agent — it has a filesystem and can
write the file itself. Each skill has a switch.

They live in `~/.hearth/skills`, so a skill you teach once applies to every
game you make, not just the folder you were in.

## Everything the agent does

Hearth replaces a terminal, so anything the terminal showed and the transcript
swallowed was something you could no longer see. Now visible: the plan the
agent is working through, images it generated or looked at, the moment the
conversation was compacted to make room, delegated agents, and questions it
asked. An action from a Codex build newer than this one renders as a plain row
rather than disappearing.

One gap, named rather than hidden: a structured question with options appears
in the transcript, but there is no picker for answering it. You reply in your
next message, which reaches the same conversation.

## Fixes

- **Playtest works in installed builds again.** The packaged app never shipped
  `playwright-core`, so the probe could not launch a browser anywhere but a
  source checkout — broken since v1.3.0.
- Stored API keys in a project are now git-ignored.
- The top bar no longer says "No agent connected" to someone signed in with
  ChatGPT.

## Coming from 1.4.0

Installed apps update automatically. Conversations, folders and settings carry
over unchanged.
