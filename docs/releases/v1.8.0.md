# Hearth v1.8.0

Hearth now keeps the native behavior of Claude Code and Codex instead of
translating both agents into a smaller shared protocol. Their questions,
approval choices, commands, skills, attachments, and session state reach the
app without losing the details that make each agent useful.

## Continue the same session in a terminal

Continue in CLI now transfers ownership of the exact running Claude Code or
Codex session to Hearth's terminal. The app finishes queued sends, stops its
native driver, starts the correct resume command, and blocks overlapping
messages until the terminal process exits. Closing and reopening the terminal
reattaches to the same handoff instead of starting an unrelated shell.

This is the escape hatch for anything that works best in the full terminal UI.
It no longer costs the conversation that led you there.

## Provider features stay intact

Claude Code uses the installed executable and its normal settings sources, so
project instructions, hooks, plugins, skills, slash commands, background tasks,
and subagents behave the way they do in the CLI. Codex keeps its own commands,
skills, MCP elicitations, approval decisions, and generated image artifacts.

Structured questions now have real controls in the transcript. They support
text, numbers, choices, multiple selections, URLs, booleans, required fields,
and secrets. Answers are sent back to the provider but are not written into
the chat log.

Approval choices also stay provider-specific. A Codex decision is returned
exactly as the server supplied it, and Claude can offer an "Allow and remember"
choice without exposing its internal permission payload in the browser.

## Sessions survive the rough edges

Native drivers can linger for an hour and reattach after a reload or a sleeping
laptop. Transcript replay shares the same serialized lane as live writes, so a
reconnect does not duplicate or reorder events. Switching providers gives the
next agent an explicit transcript handoff while preserving each provider's own
continuation handle.

Trusted project environments now load through direnv for native agents and
terminal sessions. Hearth never approves an `.envrc` on its own. If the file is
already trusted, the app uses the same variables available from that project in
a terminal.

Attachments stream into bounded, project-scoped staging instead of crossing
the socket as one large encoded message. Tokens are single use, expire, and
cannot be consumed by another project.

## A new chat is actually new

Starting a chat from Home always creates a fresh conversation, even when the
project already has history. The blank composer carries that project's
permission picker, and late responses from the chat you just left cannot reopen
it behind your back.

## Replies and games render correctly

Agent replies keep lazy and blank-separated Markdown list items together.
Headings have a visible level hierarchy, wrap long paths safely, and sit closer
to the paragraph they label.

The game pane now measures a canvas by its displayed CSS size rather than its
high-resolution backing buffer. Games that render at device pixel ratio 2 no
longer appear at half size in the top-left corner or enter a repeated shrinking
loop when their resize handler runs.
